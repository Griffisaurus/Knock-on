# Playtest 2026-10-25: Portal Express (automated self-test)

> **Automated session, not a playtest with people.** Two *scripted* players, written by stream U5 (M5), drove two Chrome windows through the game's own input (keys, mouse clicks at the screen positions of parts and ports, typing into the Library, palette and Inspector). No doc ops were injected. It checks that the build flow, the docs and co-op hold up for 30 minutes; it says nothing about fun, confusion or how long a person takes. A human session is still to run (PRODUCTION §6).

## Notes

### What worked
- **HOW_TO_PLAY §1 Quick start works as written** (after its rewrite this session): every step does what it says, and the run ends in a BANG.
- Library search found every part by a word a player might use: "stomp", "pressure", "domino", "rift", "barrier", "freeze", "beacon", "courier".
- **RIFT GATES paired themselves:** the second gate placed took the first one's colour, and the Inspector said "Paired with the other Plasma gate (#94)". BUZZ docked on the beacon's colour ("Docks on the Ignition BUZZ BEACON"), with no manual pairing.
- Lifting a part into the air by typing Y in Inspector › Transform works, and is how the drop was set up.
- Tagging from the Inspector switch, Shift+= resizing, the Wire tool on M5 ports (THE BUTTON → BUZZ BEACON call) and a Hand-of-God press of THE BUTTON in a run all worked in co-op.
- Captions in runs read well ("[BOOM] BANGSTICK", "[vwoom] … warps through RIFT GATES").

### Where the players got stuck
(Scripted players don't get stuck the way people do; these are the places the script had to be made more careful, which a person may hit too.)
- **Placing on a slope uses its bounding box:** pointing at the slope's side puts the ghost on the box's top edge, so a ball meant for the ramp sits on its rim and falls off sideways (seen in a dry run). The ghost shows it, but a hint or surface-accurate placement on slopes would help.
- **The Library keeps the last search:** clicking into the box and typing appends to the old text ("stomprift"), which finds nothing. Selecting the old text first works. Clearing the search when the Library opens (or on pick) would help.
- **Rotate keys act on the selection, not the next placement, while the Select tool is on:** a failed Library pick left the Select tool active, so Shift+T meant for the next gate tipped the selected STOMP PAD upside down (a dry run). Correct by design, but surprising.
- A run left going by an earlier session greets joiners with "Rejoined the run in progress"; edits are refused until someone stops it (Backspace).
