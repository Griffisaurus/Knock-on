# KNOCK-ON Asset Pipeline

Status: v1.3 · 2026-10-25 (as built through M5) · Owners: Tech Art (pipeline), Art Director (standards)
Related: [ART_BIBLE.md](ART_BIBLE.md) · [briefs/](briefs/README.md) · [../PART_SYSTEM.md](../PART_SYSTEM.md) (how gameplay consumes these outputs) · [../RENDERING.md](../RENDERING.md) · per-part texture sets: [D78](../dev/DECISIONS_2026-10-24.md)

This doc is the contract between Blender and the engine. If an asset follows it, it drops into the game with no hand-wiring.

## 1. Tools and versions

| Tool | Version | Use |
|---|---|---|
| Blender | **4.5 LTS** (pinned; 4.4 acceptable for look-dev) | Modelling, UVs, rigging, animation, fracture, export |
| `tools/blender/kn_tools` add-on | repo version | Part template, port ring placer, validators, one-click export |
| Substance Painter *or* Blender texture paint | any | **Required from M3** for every part's texture set (§5.2), layered over the master swatches; also critters and environments |
| gltf-transform CLI | 4.x (pinned in `package.json`) | meshopt, KTX2, pruning, dedupe |
| KTX-Software (`toktx`) | 4.3+ | Basis UASTC / ETC1S encoding |
| meshoptimizer | via gltf-transform | Simplification for LODs, compression |
| `tools/bake` (Node + Dawn/WebGPU) | repo | SDF bake, impostor bake, in-engine turntables |
| `tools/blender/render_thumbs.py` | repo | 3D part icons (`<type>.thumb.webp`) with the thumbnail rig from the exported `.glb`s; `--warm` Tinker Lab light, `--tactile` look-dev surfaces (briefs/ui_icons.md §6) |
| `tools/blender/render_tinker_lab.py` | repo | Tinker Lab key art from the exported `.glb`s, with settling and an overlap check (§12) |
| `tools/blender/_tactile.py` | repo | Look-dev only: procedural Cycles stand-ins for the D78 texture sets (briefs/shared_kit.md §7.2) |
| Git LFS | — | `*.blend`, `*.png`, `*.exr`, `*.psd`, `*.spp` |

*As built (through M5):* parts are built by Python builders, `tools/blender/make_<type>.py` with the `kn_tools` package (`template`, `ports`, `masters`, `textures`, `frac`, `cavity`, `rig`, `export`, `validate`, `bc7`, `ktx2`, …), run headless by `pnpm assets` (`tools/assets.mjs`: make → validate → export, with a self-test). Texture sets are painted procedurally in Blender (`kn_tools/textures.py`, `_tactile.py` heritage) rather than in Substance Painter. **Not used:** gltf-transform, KTX-Software / `toktx`, meshoptimizer and `tools/bake`; KTX2 / BC7 comes from the in-house encoder (D94, D97), and LODs are made in the builders. `.gitattributes` routes large binary source assets through Git LFS.

```
assets/

    lib/
      materials.blend               # master materials (linked, never appended)
      port_ring.blend               # PR_S / PR_M / PR_L collections
      fasteners.blend               # M3/M5/M8 button-head screws, rivets
      feet.blend                    # rubber feet set
      decals.blend + decals_atlas.png
      led_parts.blend               # LED domes, light bars, screen bezels
    rollers/ frame/ drive/ air/ power/ boom/ contraptions/ matter/ fun/ future/ critters/
      <type>.blend                  # one part per file; the file name = part type id
      tex/<type>.spp                # texture-set source (Painter), or painted in the .blend
      tex/<type>__<set>__basecolor.png, __normal.png, __orm.png   # exported set maps (§5.2)
    env/<environment>/...
    env/_shared/props/kn_prop_<name>.blend   # shared props kit (briefs/environments.md §7)
    fx/debris.blend, fx/sprites/...
    third_party/                    # CC0 inputs only, each listed in LICENSES.csv
  build/                            # generated by CI, never committed
    parts/<type>/<type>.glb, .shapes.json, .art.json, .frac.glb, .sdf.ktx2, .impostor.ktx2, .thumb.webp, .thumb_128.webp
                                    # + <type>.<skin>.thumb.webp / .thumb_128.webp per skin (§8)
                                    # + <type>__<set>.basecolor.ktx2 / .normal.ktx2 / .orm.ktx2 per texture set (§5.2)
assets/LICENSES.csv
```

*As built:* `assets/build/parts/<type>/` holds `<type>.glb`, `.art.json`, `.shapes.json`, `.report.json` (the build's validation report), `.frac.glb` for breakables, and the texture set as `<type>.tex.{albedo,normal,orm}.png` plus `.ktx2` (D88, D97; one set per part, not `<type>__<set>.*`). No `.sdf.ktx2` or `.impostor.ktx2` is baked. The 3D part icons are served at `/parts/<type>/<type>.thumb.webp`: a pipeline render in `assets/build/parts/<type>/` wins, otherwise the rendered icon set in `art/style-samples/icons/` (the Vite plugin `partThumbs`, `apps/game/vite.config.ts`). Environments build to `assets/build/env/<id>/` (`<id>.glb`, `<id>.env.json`, the IBL and the LUT; M5 adds `hangar`, one glb per bay `hangar_<preset>.glb`, and `moon`, `moon.glb` + `moon_boulders.glb`, with authored heightfields and terrain textures; `<id>.env.json → textures` lists an environment's own texture set, the baked Earth), and the generated `packages/parts-data/src/env_<id>.ts` tables (DATA_FORMATS §8.3), props to `assets/build/env/props/`, and the decal atlas to `assets/build/kit/`.

## 3. Blender scene conventions

### 3.1 Units and axes
- Metric, unit scale 1.0, **1 BU = 1 m**. Grid overlay 0.1 m (**1 game cell**). Footprints of **placed devices** are whole or half cells. **Free bodies** (Rollers, Yolk, critters, free explosives such as Bangstick and Powder Keg, and loose props such as Topple Tiles, Stackers, Pane / Vase) are exempt: they use their catalogue size (GAME_SPEC §12, §19), which may be fractional.
- Blender **Z-up**. The exporter converts to the glTF/engine **Y-up**.
- **Front = −Y** (the face toward the default game camera, Blender's Front view, numpad 1).
- Apply all transforms. No negative scale. Mirroring happens in the engine.

### 3.2 Origin
| Part kind | Origin |
|---|---|
| Rotating (cogs, wheels, turbines, fans) | Axle centre |
| Hinged (Fulcrum, Flap, Bonker, Paddle) | Hinge axis centre |
| Free bodies (Rollers, Yolk, critters, loose props, and free explosives: Bangstick, Powder Keg, Jitterjuice, Skyrocket) | Centre of mass |
| Static or placed devices | Bottom centre of the footprint (z = 0 on the floor) |
| Dynamic placed devices that stand upright on the floor (Wick, Hourglass, Skyshow, Popper, Snaptrap, Fishbowl) | Bottom centre of the footprint, like placed devices. The engine computes the centre of mass from the collision shapes, so no COM origin is needed |

### 3.3 Collections and object naming
One part per `.blend`. Use the `kn_tools → New Part` template, which creates these collections.

| Collection | Object names | Contents |
|---|---|---|
| `RENDER` | `<type>__<piece>` | LOD0 meshes. Moving pieces are parented to `PIVOT__*` empties |
| `LOD1`, `LOD2`, `LOD3` | `<type>__<piece>__L1` … | 50 % / 25 % / 8 % of LOD0 tris |
| `COL` | see §3.4 | Physics collision |
| `PORT` | `PORT__<channel>__<name>` | Port ring placements (empties + linked PR instance) |
| `SENSOR` | `SENSOR__<kind>__<name>` | Sensor volumes (convex meshes). `<kind>` vocabulary below |
| `EMIT` | `EMIT__<fx>__<name>` | VFX and audio spawn points (empties, +X = direction) |
| `PIVOT` | `PIVOT__<name>` | Code-driven transforms (empties; custom property `axis = x/y/z`, `min`, `max` in degrees or metres) |
| `SCREEN` | `SCREEN__<name>` | Flat quads with `kn_screen`; custom properties `kind = 7seg/bar/icon/text`, `digits` or `cells` (§3.7; bezel sizes in briefs/shared_kit.md §5) |
| `CAVITY` | `CAVITY__<name>` | Closed inner-volume meshes for containers drawn by the fill pass (§3.10) |
| `FRAC` | `FRAC__<n>` | Pre-fractured chunks (breakables and explosives, §7) |
| `RIG` | `RIG` armature + `RAG__<bone>` capsules | Critters and complex mechanisms (§6) |

Names are lower_snake after the prefix: `PORT__power__in`, `EMIT__flame__wick`, `PIVOT__lever`.

**Channels** (the `PORT__` vocabulary): `impact, signal, spin, tension, power, light, heat, air, fluid, sound, lure, field`.

**Sensor kinds** (the `SENSOR__` vocabulary) are not the same list:
- **Volume kinds:** `trigger` (contact or impact trigger; `threshold` in N·s), `pressure` (load on a deck or pad; `threshold` in kg), `intake` (absorbs Matter, up to the part's `capacity`), `catch` (holds or carries the bodies resting in it).
- **Receive kinds:** a channel name, for a volume through which the part *receives* that channel without a link: `impact`, `light`, `heat`, `air`, `fluid`, `sound`, `lure`, `field` (e.g. `SENSOR__heat__flame`, `SENSOR__light__panel`, `SENSOR__sound__ear`). `signal`, `spin`, `tension` and `power` only travel over links, so they are never sensor kinds. Prefer `trigger` over `impact` for button-like contact triggers.

### 3.4 Collision (`COL`)
Prefer the cheapest shape that plays right. The engine converts these to Jolt shapes.

| Object name | Jolt shape | Authoring |
|---|---|---|
| `COL__sphere__n` | Sphere | UV sphere mesh; the radius is read from its bounds |
| `COL__box__n` | Box (rounded with `convex_radius`) | Cube mesh, any rotation |
| `COL__capsule__n` | Capsule | Cylinder-ish mesh along local Z; the exporter fits it |
| `COL__cylinder__n` | Cylinder | Cylinder mesh along local Z |
| `COL__hull__n` | ConvexHull | Convex mesh, ≤ 64 vertices |
| `COL__mesh__n` | Mesh (static parts only) | Triangle mesh ≤ 4k tris |
| `COL__heightfield__<cx>_<cy>` | HeightField (environments only) | Per 32 m terrain chunk; see briefs/environments.md |
| `COL__wheel__n` | (vehicle wheel) | Zippy only |

Rules: **≤ 12 shapes per part** (critters use the ragdoll set instead), shapes may overlap, and no shape may be thinner than 5 mm. Optional per-shape overrides: `restitution`, `friction` (custom properties next to `phys`). Optional per-shape tag **`sharp = true`**: contacts with that shape pop Helios (SIMULATION §5.1). Use it only on the shapes that are visibly sharp or meant to pop: blades, Cog teeth, the Cork Blaster cork. Clear tubes and gutters use `COL__mesh` inner surfaces (static) or compound hulls (movable). Physics material per shape: custom property `phys = powder|rubber|steel|wood|glass|paper|brick|ceramic|latex|fur|fabric|concrete|soil|regolith` (see [../SIMULATION.md §4.3](../SIMULATION.md)).

### 3.5 Ports, sensors, emitters, pivots
- **Ports:** `PORT__<channel>__<name>`. Place the empty first, then `kn_tools → Snap Port Ring (S/M/L)` instances the linked ring there. Custom properties: `dir = in|out|both`, `size = S|M|L`, optional `max_links`, `broadcast` and `kind`.
  - `max_links`: links this port accepts, per port. Default **1**, cap **8**. The one exception: a Signal **output** that also sets `broadcast = true` may declare up to **64** (T-PLUNGER `out` is the only v1 user). Must equal `maxLinks` / `broadcast` in `<type>.part.json` ([../PART_SYSTEM.md §3](../PART_SYSTEM.md)); `validate:parts` rejects anything else.
  - `kind`: the socket variant (shared_kit.md §1.3). `axle` for Spin ports and Sheave axles, `hook` or `end` for tension ports; omitted = the plug socket.
- **Sensors:** `SENSOR__<kind>__<name>`, e.g. `SENSOR__trigger__button`, `SENSOR__intake__top`, `SENSOR__heat__flame` (kinds in §3.3). Custom properties: `threshold` (N·s for impact triggers, kg for pressure), `cooldown` (s).
- **Emitters:** `EMIT__spark__fuse_tip`, `EMIT__muzzle__barrel`, `EMIT__exhaust__nozzle`, `EMIT__wind__front`, `EMIT__beam__lens`, `EMIT__spout__nozzle`. Audio uses the same empties.
- **Pivots:** every moving piece hangs under exactly one `PIVOT__` empty. Rotation axis and limits go in custom properties. The engine drives the pivot from sim state; the mesh never animates itself unless it's a clip (§6).

### 3.6 LED groups
- LED faces use `kn_led`. Assign **vertex colour attribute `led`**: R channel = group index / 255 (0–15), G = default brightness (0–1).
- Declare each group in a custom property on the root object: `led_groups = "0:status,1:port_power_in,2:charge_bar"`.
- Port-ring LEDs are handled automatically by the linked ring; don't add them to `led_groups`.

### 3.7 Screens
`SCREEN__<name>` quads with UVs filling 0–1 and `kn_screen`. Properties: `kind` (`7seg` / `bar` / `icon` / `text`), `digits` or `cells`, `color` (channel name or brand colour). The engine renders the content into an atlas region.

### 3.8 Root custom properties (the exporter reads these into `.art.json`)
`kn_type` (id) · `kn_family` · `kn_class` (S/M/L/XL) · `kn_footprint` ("w,h,d" in cells; whole or half cells for placed devices, the catalogue size for free bodies, §3.1) · `kn_mass_hint` (kg) · `kn_skins` (comma list) · `led_groups` · `kn_notes`.

**Gameplay hint properties** (`kn_break_impulse`, `kn_mortar_break`, `kn_pop_speed`, `kn_pop_heat`, `kn_magnetic`, `kn_payload_max`, …) record the brief's target values. The exporter copies any numeric or boolean `kn_*` property not listed above into `.art.json → hints`. **The authoritative values live in `<type>.part.json`** ([../PART_SYSTEM.md](../PART_SYSTEM.md)); `validate:parts` warns when the two disagree.

### 3.9 Device sockets for critters
Devices that a critter uses (Hamster Drive, Pedal Rig, Fishbowl, Trap Box, Buzz beacon) may contain a small `RIG` armature (≤ 12 bones) whose `socket_*` bones are attachment and IK targets for the critter (feet, hands, pelvis, mount and exit points). Socket bones follow pivots via Copy Transforms constraints. The exporter writes them to `.art.json → sockets`. The validator allows a device `RIG` only when every bone is named `root`, a pivot mirror, or `socket_*`.

### 3.10 Containers and fill levels
Parts that visibly hold Matter or contents mark their inner volume with a closed, manifold mesh `CAVITY__<name>` in the `CAVITY` collection, inset 3–4 mm from the inner wall. The complete list: **Scoop, Tank, Hourglass (two cavities), Grit Hopper, Marble Hopper, Goo Vat, Fishbowl, Sprinkle Can, Jitterjuice** (`matter = fill`, fixed level). The Sponge has no cavity: it uses the engine wetness overlay plus shape keys.
- Custom properties: `matter = sand|water|marble|goo|fill` (`fill` = a cosmetic liquid with no Matter material) and, on emitting or absorbing containers, `capacity` (litres, grains or marbles as the brief states; mirrors the part's capacity property).
- The exporter bakes a **fill LUT** (64 entries: fill fraction by volume → level-plane height, in local space) into `.art.json → cavities`. Each entry also carries `volume` (litres), `min` / `max`, the closed cavity `mesh` (for clipping at any tilt) and, for a cavity under a pivot, `tilt` LUTs across the pivot's range (`kn_tools/cavity.py`, M4). The validator rejects open or inside-out cavities (`10.cavity`).
- The renderer draws the contents as a **world-space level plane** clipped to the cavity (it stays level when the part tilts), with a surface profile chosen by the engine from the part state: `flat` (liquids, at rest), `crater` (granular contents draining) or `pile` (granular contents receiving).
- Real Matter particles exist only near outlets and intakes (SIMULATION §8).

## 4. Modelling standards

| Topic | Standard |
|---|---|
| Topology | Clean quads where it deforms (critters, Helio, Bellows); otherwise anything that shades cleanly. No n-gons on curved surfaces. Manifold, watertight meshes (required for SDF bake). |
| Bevels | ART_BIBLE §2. Prefer real geometry bevels (Bevel modifier, applied at export) + weighted normals. No "bevel shader". |
| Normals | Weighted normals / harden normals. No smoothing artifacts on flat faces (check with a matcap). |
| UVs | Channel 1: unique, non-overlapping, 4 px padding at 1024². Channel 2 (optional): tileable trims. Texel density **1024 px/m** for parts, **2048 px/m** for critter faces. |
| Small details | Fasteners, panel lines and text under 3 mm go into normal and decal maps, not geometry, at LOD1+ |
| LODs | LOD1 50 %, LOD2 25 %, LOD3 8 % of LOD0 tris. meshoptimizer first pass, then manual silhouette fixes. LOD2 interiors are simplified to coloured blocks; LOD3 shells go opaque. **LOD3 floor:** LOD3 may go down to a 12-tri box or a 20-tri icosahedron even when that is below 8 % of LOD0 (small instanced parts such as Topple Tiles, Stackers and Glint); the validator's LOD-ratio check (§9) accepts these primitive floors. |
| Instancing-heavy parts | Topple Tiles, Brik, Stackers, Pins, Glint/Bearing: **LOD0 ≤ 300 tris**, 1 material, no transmission |

**Budgets by class** (LOD0):

| Class | Tris | Texture set | Materials | Bones | Typical effort |
|---|---|---|---|---|---|
| S | 300–3,000 | 1024² unique set | ≤ 2 textured | 0 | 1 day |
| M | 3,000–10,000 | 2048² | ≤ 3 textured | 0 (pivots) | 2.5 days |
| L | 10,000–25,000 | 2048² + 1024² detail | ≤ 3 textured | ≤ 12 (optional) | 5 days |
| XL (critter) | 25,000–60,000 (robot critters Dusty and Buzz: 15,000–25,000) | 4096² (robot critters 2048²) + 1024² eyes/teeth | ≤ 4 textured | ≤ 80 | 10–12 days + animation |
| Environment | 200k–1M (streamed chunks); the Studio is ≤ 40k by design (briefs/environments.md §1) | trims + 2048² hero sets | — | — | 12 days |
| Environment prop (`kn_prop_*` kit) | E-S 300–2,000 · E-M 2,000–8,000 · E-L 8,000–30,000 (briefs/environments.md §0.4, §7) | kit trims 2048² · 1024² unique · 2048² hero | ≤ 2 / 3 / 3 | — | 0.5 / 1 / 2 days |

Class efforts are pre-pivot figures. The texture set adds about 0.5 day (S), 1 day (M) and 2 days (L) per part (PRODUCTION §3).

**Material slots:** the "textured" limit counts **texture sets** (§5.2), not slots. One set usually covers every master slot of the part that shares its UV1 layout (body enamel, brass pulls, rubber feet in one atlas), so most parts have one set. Masters that never take a set (`kn_poly_*` apart from its Thickness map, `kn_glass`, `kn_chrome`, `kn_led`, `kn_screen`, `kn_decal`, the linked shared kit) don't count. Hard cap: 12 slots per part. Instancing-heavy parts: exactly 1 slot and 1 set.

### 5.2 Texture sets
From M3 **every part has a unique texture set** layered over its masters ([D78](../dev/DECISIONS_2026-10-24.md)); masks alone are not final art. Parts made before M3 get theirs in the texture pass (M1 parts first, PRODUCTION §3).

| Map | Content | Space / format (source) |
|---|---|---|
| `basecolor` | Final albedo: the master swatch as the base layer, plus grain, print, patina, worn edges and polish (ART_BIBLE §4 limits) | sRGB, 8-bit PNG |
| `normal` | Grain, panel lines, moulding marks, worn-edge rounding, small fasteners and text (< 3 mm). Not the tiling detail layer | OpenGL +Y, 16-bit PNG |
| `orm` | R cavity occlusion, G final roughness (polish, patina), B metallic (bare metal where enamel is worn through) | linear, 8-bit PNG |
| `emissive` (optional) | Emissive mask only; colour stays engine-driven (`kn_led`, `kn_screen`) | linear, 8-bit PNG |
| `thickness` (poly and glass) | Shell thickness in metres | linear, 16-bit PNG |

- **How it layers:** the master keeps the response the set can't carry (coat, sheen, transmission, IOR, anisotropy, the detail layer); the set supplies albedo, normal and ORM. In Blender, the set plugs into the `KNM_<family>` group's `Set` inputs (briefs/shared_kit.md §7.2); the engine samples the set's array layers for the slots that use it (RENDERING §6.1).
- **One set per UV1 layout.** A set covers all the slots that share the part's UV1 atlas. Each textured slot names its set in a custom property `kn_set = <set>` (lower_snake, e.g. `body`, `drum`).
- **Sizes** (all maps of a set are the same size): **S 1024² · M 2048² · L 2048² + an optional 1024² second set · XL as in §4**. Instancing-heavy parts: one 1024² set. Environment props: briefs/environments.md §0.4.
- **Texel density** stays 1,024 px/m (parts) and 2,048 px/m (critter faces). Padding: 8 px at 2048², 4 px at 1024², dilated so mips never bleed.
- **Exempt** (no set): `kn_poly_*` (Thickness map only), `kn_glass`, `kn_chrome`, `kn_led`, `kn_screen`, `kn_decal`, and the linked shared kit (port rings, fasteners, feet, LED parts), which carries its own shared sets.
- **Naming:** sources `assets/src/<family>/tex/<type>__<set>__<map>.png` (`<map>` = `basecolor`, `normal`, `orm`, `emissive`, `thickness`), Painter project `tex/<type>.spp`. Build output `assets/build/parts/<type>/<type>__<set>.<map>.ktx2`, listed in `.art.json → textures` with size and the slots that use each set. **Interim (D88):** until an offline UASTC/BC7 transcoder is installed, the build ships `<type>.tex.{albedo,normal,orm}.png` (albedo sRGB; normal OpenGL +Y and ORM linear), and `.art.json → textures` records the file names, format and colour space. **As built (M4, D97):**
  - **Encoder:** the in-house encoder (`kn_tools/bc7.py`, `ktx2.py`; `node tools/assets.mjs --ktx2` / `--ktx2-only`) writes `<type>.tex.{albedo,normal,orm}.ktx2`: BC7 with full mips, zlib supercompression, listed as `textures.ktx2` in `.art.json`.
  - **Loading:** the engine loads the KTX2 when the adapter has `texture-compression-bc`. Otherwise it uses the PNG, which stays the source and the fallback.
  - **Not yet:** UASTC/Basis, which ASTC for Apple would need.
- Skins that change paint colour get their own `basecolor` (and `orm` if the finish changes) under `<type>__<set>.<skin>.<map>.ktx2`; skins that only swap a master need none.

### 5.3 Engine texture arrays and compression
- The engine packs textures into **2D arrays by size** (1024², 2048², 4096²) and by map (albedo sRGB, normal, ORM). Every authored texture must be exactly one of those sizes.
- Encoding (target; as built today: in-house BC7 + zlib, D97): **every part texture set (BaseColor, Normal, ORM) → KTX2 UASTC + RDO + zstd** with full mips, which transcodes to **BC7** on desktop (D78) and ASTC 4×4 on Apple. ETC1S is used only for environment backdrops (`E-B`) and HLOD proxies.
- Download cost (estimate): about 7 MB per 2048² set and 2 MB per 1024² set on the wire. Parts are still fetched on first use (ARCHITECTURE §6.5), so a world only downloads the sets it shows.

## 6. Animation and rigging

| Approach | When | Authoring |
|---|---|---|
| **Procedural pivots** (default) | Anything mechanical: rotation, translation, levers, blades, springs that only compress | `PIVOT__` empties + limits. No keyframes. |
| **Shape keys** | Inflate (Helio), squash (Puffer bellows, Sponge), spring coil compression, critter faces | Named `sk_<name>`, values 0–1 |
| **Baked clips** | Critters; complex multi-part mechanisms (Gotcha Box pop, Grabber, Big Top recoil) | Actions named `<type>__<clip>`, 30 fps, root-motion free |

**Critter rig standard:** ≤ 80 deform bones, ≤ 4 influences per vertex, root bone `root` at the floor under the centre of mass, `head`, `spine_01–03`, standard limb chains, tail chain (≤ 8). Face via shape keys (ART_BIBLE §8). The ragdoll uses `RAG__<bone>` capsules with custom properties `swing_deg`, `twist_deg`, `mass`.

**Required critter clips:** `idle`, `idle_alt`, `walk`, `run`, `chase`, `flee`, `startled`, `tumble` (ragdoll blend-in), `getup`, `dizzy`, `trapped`, `celebrate`, `sleep`, `sniff`, `emote_happy`, `emote_angry`, `emote_confused`, plus the role clips listed in each brief.

## 7. Fracture (breakables and explosives)
- Build chunks in `FRAC` using Cell Fracture or a Geometry Nodes Voronoi setup: **6–24 chunks** (explosives **4–24**: an explosive's macro chunks spawn on detonation, e.g. Bangstick `macroChunks: 4`), larger toward the visual centre, with readable shapes (planks split along the grain, glass in shards, bricks at mortar lines).
- Inner faces use `kn_interior_<material>`. Each chunk is ≤ 1,500 tris and manifold.
- Each chunk gets `COL__hull` auto-generated from its own hull unless authored.
- Micro debris comes from the shared `fx/debris.blend` library (12–20 shards per material, 20–200 tris).

## 8. Export pipeline

`kn_tools → Export Part` (or headless in CI: `blender -b <file> --python tools/blender/export_part.py`).

| Output | Contents |
|---|---|
| `<type>.glb` | Render nodes `LOD0..LOD3`, pivots as nodes, skins and clips, material slots as master IDs (resolved by the engine, not embedded) |
| `<type>.shapes.json` | Jolt shape list (type, transform, dims or hull points, phys material) |
| `<type>.art.json` | Footprint, bounds, ports (name, channel, dir, size, transform), sensors, emitters, pivots (axis, limits), screens, LED groups, skins, clip list, mass hint |
| `<type>.frac.glb` | Fracture chunks + their hulls (breakables only) |
| `<type>.sdf.ktx2` | 32³ (S/M) or 64³ (L/XL) signed distance field, r16f, for GI, AO and particle collision |
| `<type>.impostor.ktx2` | Octahedral impostor, 12×12 views, 2048² (albedo + normal-depth) |
| `<type>__<set>.basecolor.ktx2`, `.normal.ktx2`, `.orm.ktx2` (+ `.emissive`, `.thickness`) | The part's texture sets, UASTC + RDO, full mips (§5.2–5.3) |
| `<type>.thumb.webp`, `<type>.thumb_128.webp` | 512² and 128² 3D part icons for every UI use (rendered by `tools/blender/render_thumbs.py` with the warm Tinker Lab rig, matched to the engine; briefs/ui_icons.md §6) |
| `<type>.<skin>.thumb.webp`, `<type>.<skin>.thumb_128.webp` | The same pair for every skin in `kn_skins` |

Post-process (CI): `gltf-transform` dedupe → prune → meshopt → KTX2 → size report. The build fails if the part exceeds its class budget by more than 10 %.

*As built:* `export_part.py` writes the `.glb`, `.art.json`, `.shapes.json` and (breakables) `.frac.glb`; the texture set is exported as PNG and encoded to KTX2 / BC7 by the in-house encoder (§5.2); `tools/assets.mjs` writes a `.report.json` per part. The `.sdf.ktx2` and `.impostor.ktx2` outputs and the gltf-transform post-process aren't built: the GI stamps instance boxes, impostors are baked on the GPU at first use (RENDERING §0), and meshes ship uncompressed. Thumbnails are rendered separately by `render_thumbs.py`.

## 9. Validation (`validate_part.py`, CI-blocking)

1. File name = `kn_type`. Collections and prefixes as in §3.3. No unknown objects.
2. Scale applied, no negative scale, origin per §3.2, front = −Y (checked against port and emitter directions declared in the brief).
3. Bounds match `kn_footprint` ± 0.02 m. Placed devices: whole or half cells; free bodies: catalogue size (§3.1).
4. Tris per LOD within class budget; LOD ratios ±10 % (except the LOD3 primitive floors, §4).
5. Materials: only linked masters; every textured slot names an existing set (`kn_set`); texture-set count within budget; ≤ 12 slots total (§4).
6. Textures: allowed sizes only; sRGB flags correct (BaseColor only).
7. Collision: present, ≤ 12 shapes, hulls ≤ 64 verts, no shape thinner than 5 mm.
8. Ports: linked ring instance present, size matches `size`, faces outward (not into the housing); `max_links` within the §3.5 limits.
9. Pivots have `axis`; every moving piece is under exactly one pivot.
10. Meshes are manifold (for SDF bake).
11. Critters: bone count, weights ≤ 4, required clips present, ragdoll capsules for all major bones.
12. `LICENSES.csv` covers every file in `third_party/` that the part references.
13. Texture sets (from M3; a warning for parts still awaiting the texture pass): every non-exempt part has at least one set (§5.2); each set has `basecolor`, `normal` and `orm`, all the same size, and that size matches the class; file names follow §5.2 and no unlisted files sit in `tex/`; BaseColor stays within linear 0.03–0.85 (99th percentile), and each slot's mean colour keeps the linked master's hue within ±4 % value (ART_BIBLE §3.1); ORM metallic is 0 or 1 (soft edges ≤ 4 px); normal maps are OpenGL +Y.

## 10. Provenance and licensing
- **Ship-allowed third-party inputs:** CC0 only (Poly Haven HDRIs and textures, ambientCG textures, CC0 audio). Each is logged in `assets/LICENSES.csv`: `asset, source_url, license, author, date, used_by`.
- **Placeholder only:** CC0 models (Kenney, Quaternius, Poly Pizza CC0) in `assets/src/third_party/placeholder/`. CI excludes this folder from release builds.
- **Never:** traced or derived content from the 1993 game (`reference/tim1/`), real brand logos, or AI-generated images used as textures without an explicit decision by the art director.

## 12. Look-dev, icon and key-art renders

All three run headless in Blender on the **exported** part `.glb`s, so they show what the engine loads. Outputs land in `art/style-samples/` for look-dev; none of them are shipped textures.

| Command | Output |
|---|---|
| `blender -b --factory-startup -P tools/blender/render_tinker_lab.py -- <out.png> [--res 1920x1080] [--samples N] [--view hero\|wide\|lobby] [--no-volume] [--check] [--strict]` | Tinker Lab key art (D78): `tinker_lab_key.png` (hero, 1920 × 1080) and `tinker_lab_lobby.png` (the shallow-focus lobby and title backdrop) |
| `blender -b --factory-startup -P tools/blender/render_thumbs.py -- <out_dir> [--types a,b] [--size 512] [--crop128] [--warm] [--tactile] [--samples N]` | `<type>.thumb.webp` (or `.thumb_128.webp`) 3D part icons; `icons/` holds 28 warm tactile icons at 256² |

**Key-art placement checks.** `render_tinker_lab.py` settles every resting part and MOCHI onto its real support from the evaluated (posed) mesh, casting rays three ways: part vertices down, support vertices up, and a 17 × 17 grid over the footprint (vertex-only rays miss crossed bricks). It then runs a triangle-level overlap check (BVH) on everything placed. `--check` prints the report without rendering; `--strict` fails the render if any pair interpenetrates. The final hero render passed with **0 overlapping pairs**.

**Tactile stand-ins.** `--tactile` and the key art use `tools/blender/_tactile.py`: procedural Cycles surfaces for the D78 texture sets (enamel with worn edges and darkened cavities, wood grain along the longest axis, brass and copper patina, scratched steel, paper fibre, rubber, brick, cord, ceramic), coloured from the master table. They are the target for the texture pass (§5.2), not shipped materials.

**Known issue (fonts).** Blender renders the bundled `assets/src/lib/fonts/Unbounded-Bold.ttf` with "T" drawn as "V", although the glyph is present in the cmap (checked with fontTools). The Tinker Lab chalkboard text was switched to DejaVuSans-Bold. The decal atlas (`build_decals.py`) also sets name plates in Unbounded and must be checked for the same fault. Tracked in [PIPELINE_STATUS.md](PIPELINE_STATUS.md#known-issues-look-and-feel-pivot).
